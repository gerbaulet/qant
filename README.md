# Quant Server

Quant Server is a deliberately small OpenRouter relay for the Quant iOS app. It
runs OpenRouter chat completions independently of the phone connection and lets
the app retrieve the result after reconnecting.

The OpenRouter key is supplied by the phone for each job. The server never writes
the key or the request body to disk and never includes either in logs. Running
requests necessarily keep the key and request in process memory until the
OpenRouter call has finished. Persisted job files contain only hashed ownership
metadata, status, and the final response and are deleted after the configured
TTL.

Every iPhone keeps its own OpenRouter key in its own iOS Keychain. There is no
shared key in the Compose configuration or on the server.

## Requirements

- A Linux host with Docker Engine and Docker Compose
- Tailscale on the host and on every iPhone
- Tailscale HTTPS and MagicDNS enabled for the tailnet

For a fresh Debian 13 server, follow the automated, two-phase
[host setup and deployment runbook](docs/server-setup.md). It configures an
administrator SSH key, updates, automatic security patches, swap, Docker,
Tailscale, fail2ban, nftables, and SSH hardening without risking an immediate
lockout.

## Start the server

```sh
make up
make status
make health
```

The Makefile provides the usual lifecycle commands, so direct Docker Compose
commands are not required:

| Command | Effect |
| --- | --- |
| `make up` | Validate, build, and start the server in the background |
| `make down` | Stop and remove containers while preserving the job volume |
| `make start` | Start existing containers without rebuilding |
| `make stop` | Stop containers without removing them |
| `make restart` | Restart the running server |
| `make status` | Show container status |
| `make logs` | Follow the latest server logs |
| `make health` | Check the local health endpoint |
| `make tailscale-up` | Publish the server privately using Tailscale Serve |
| `make tailscale-down` | Disable the server's Tailscale HTTPS proxy |
| `make tailscale-status` | Show the active Tailscale Serve configuration |
| `make deploy-server` | Deploy the current source to `server01.tail851aa0.ts.net` as `clemens` (`make deploy` is a shorter alias) |
| `make help` | List all available commands |

Override `DEPLOY_HOST` or `DEPLOY_USER` on the command line when deploying to a
different provisioned host or with a different administrator account.

`make logs` shows a privacy-safe lifecycle line when an analysis job is
accepted, completed, or fails. These lines contain no API key, request body,
model, meal data, or Tailscale identity.

The container is published only on host loopback. Do not change that binding to
`0.0.0.0` when using Tailscale Serve.

Expose it privately inside the tailnet:

```sh
make tailscale-up
make tailscale-status
```

If the local Tailscale installation requires elevated permissions, pass the
command explicitly, for example `make TAILSCALE="sudo tailscale" tailscale-up`.
`make tailscale-down` disables Tailscale Serve on HTTPS port 443. It does not
disconnect the host from the tailnet and does not reset the complete Serve
configuration.

Tailscale prints an address similar to:

```text
https://quant-server.example-tailnet.ts.net/
```

Enter that root address in Quant. Use **Tailscale Serve**, never Tailscale
Funnel. Serve adds the authenticated `Tailscale-User-Login` header that Quant
Server requires. The backend trusts that header only because it is reachable on
host loopback.

For least privilege, tag the server and grant only the intended user or group
access to TCP port 443. A minimal policy fragment is:

```json
{
  "tagOwners": {
    "tag:quant-server": ["autogroup:admin"]
  },
  "grants": [
    {
      "src": ["you@example.com"],
      "dst": ["tag:quant-server"],
      "ip": ["tcp:443"]
    }
  ]
}
```

Adapt the identity before applying the policy. Existing broader grants are
additive and can still provide access.

## API

- `GET /healthz` — unauthenticated container health check
- `POST /api/v1/jobs` — create or resume an idempotent chat-completion job
- `GET /api/v1/jobs/{id}` — retrieve job status and result
- `GET /api/v1/key` — fixed OpenRouter metadata proxy
- `GET /api/v1/models` — fixed OpenRouter model-catalog proxy
- `GET /api/v1/model/{provider}/{model}` — fixed model metadata proxy
- `POST /api/v2/analysis-jobs` — create or resume a complete Quant nutrition-analysis job
- `GET /api/v2/analysis-jobs/{id}?wait=25` — wait for or retrieve the final structured result
- `DELETE /api/v2/analysis-jobs/{id}` — acknowledge durable local storage and delete the server result

Chat requests require:

- `Tailscale-User-Login`, injected by Tailscale Serve
- `Authorization: Bearer <the phone's OpenRouter key>`
- `Idempotency-Key`, generated by Quant from its persisted analysis operation

The relay is not a general HTTP proxy. Every upstream request targets the fixed
OpenRouter base URL.

## Configuration

| Variable | Default | Meaning |
| --- | --- | --- |
| `QUANT_LISTEN_ADDR` | `:8080` | HTTP listen address inside the container |
| `QUANT_DATA_DIR` | `/data` | Short-lived job result directory |
| `QUANT_OPENROUTER_BASE_URL` | `https://openrouter.ai/api/v1` | Fixed upstream base URL |
| `QUANT_ALLOW_UNAUTHENTICATED` | `false` | Allow loopback development without a Tailscale header |
| `QUANT_MAX_CONCURRENT_JOBS` | `3` | Maximum simultaneous OpenRouter calls |
| `QUANT_MAX_REQUEST_BYTES` | `26214400` | Maximum request body size |
| `QUANT_MAX_RESPONSE_BYTES` | `10485760` | Maximum upstream response size |
| `QUANT_JOB_TTL` | `168h` | Maximum result retention period; acknowledged v2 results are deleted earlier |
| `QUANT_UPSTREAM_TIMEOUT` | `2m` | Timeout for one OpenRouter call |

`QUANT_ALLOW_UNAUTHENTICATED=true` is only for local development. It accepts
requests without a Tailscale identity only when the direct peer is loopback.
